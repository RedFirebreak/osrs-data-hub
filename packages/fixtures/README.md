# HA Exporter v1.5 fixture payloads

Wire-exact request bodies as the HA Exporter plugin (`xXD4rkDragonXx/runelite-homeassistant-data-exporter@0ec2a36`, v1.5) would send them. They are meant to seed `packages/fixtures` until real captures from a side-loaded plugin replace them (handoff §17 M0).

## How they were produced

- **Serializer:** RuneLite's own `net.runelite.http.api.RuneLiteAPI.GSON` from `net.runelite.arn:http-api:1.2.25` (the http-api that `net.runelite:client:1.13.0` depends on), on Gson 2.8.5. That's the instance RuneLite binds for `@Inject Gson` (`RuneLiteModule.java:138`).
- **Classes:** mirror classes whose field declarations are copied verbatim from the plugin's `data/*` and `events/*` classes, plus real RuneLite types (`WorldPoint`, `GameState`, `LootRecordType`, `Skill`, `Experience`, `EquipmentInventorySlot`). Generator: `../harness/src/Gen.java`. The plugin itself was **not** built or run.
- **Logic ports:** loot stack merging and rarity, the death kept/lost split, stats and virtual levels, the levelUp ordering, and the per-connection filter re-serialization were ported line by line (see "Code path" below).
- **Values:** item ids and high-alch values come from the OSRS Wiki item mapping; GE prices come from `prices.runescape.wiki/api/v1/osrs/latest` (fetched 2026-09-28). NPC ids come from RuneLite's `net.runelite.api.NpcID`. Loot rarities come from the plugin's own `npc_drops.json`.
- **Identity:** each `accountHash` is a real salted SHA-224 of a fictional `Client#getAccountHash()` long (`Utils.accountHash`), so each is 56 lowercase hex characters. The names are fictional stand-ins: Zezima (main), Lynx Titan (PKer), Iron Mira (ironman). Every `eventId` is a random v4 UUID generated deterministically. Timestamps are epoch ms around `1790000000000` (2026-09-21T13:33:20Z).

**Format:** each file is a single compact line with no trailing newline, which is exactly what goes on the wire. Use `jq . file.json` to read one. Gson escapes HTML characters: `'` → `'`, `=` → `=`, `&` → `&`, `<`/`>` → `<`/`>`. You'll see this in `Black d'hide body`, `Kree'arra` and `...Special:Search?search=...`. Any JSON parser decodes these escapes, so never match raw bytes.

**Code path** references are relative to `src/main/java/haexporterplugin/` in the plugin repo.

## Pairing and raw HTTP

| File                               | Content                                                                                                                                                                                                             |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pair-request.json`                | Pairing body. The code is a JSON **string** and can have leading zeros. `HomeAssistUtils.java:365-368`.                                                                                                             |
| `pair-request.http`                | Raw request captured from OkHttp 3.14.9 built exactly like `getToken` (`HomeAssistUtils.java:362-376`). There's no token header.                                                                                    |
| `events-request.http`              | Raw ingest request built exactly like `buildRequest` (`HomeAssistUtils.java:253-263`). The explicit `Content-Type: application/json` is **overridden** on the wire by the body's `application/json; charset=utf-8`. |
| `redirect-301-downgraded-get.http` | What arrives after the hub (or its proxy) answers the POST with 301/302/303: OkHttp re-sends it as a **GET without a body, still carrying `X-Osrs-Token`**. For 307/308 OkHttp doesn't follow the redirect at all.  |

In the captures the `User-Agent` is `okhttp/3.14.9`. Inside RuneLite an interceptor replaces it with `RuneLite/<version>-<commit>` (`RuneLite.java:112,420-437`, client 1.13.0 sources). The `Host` is the local capture server.

## Caveats

- Doubles such as `rarity` are written by `Double.toString`. Small values use exponent notation (`2.0E-4`), and the last digit may differ between JREs. Parse them as numbers.
- `world` numbers and their `worldTypes`, coordinates, the diary and combat-task text, and the unresolved clog name are realistic but illustrative. Event shapes, field order, types and omission rules are the verified part.
